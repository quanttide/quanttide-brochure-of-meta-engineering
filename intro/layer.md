# 分层

这篇文章介绍元工程的分层的来源与建模。

## 定位

元工程不直接解决问题，而是把不可解决的问题分解成可以解决的问题。

## 来源

我们做一篇经济学文章，分为以下四个步骤：

1. 描述现象：我们观察到电商平台的搜索算法对平台生态有很多影响，比如说商家排到前面会刷评论，导致平台的评论体系崩溃。
2. 数理建模：商家面临一个跨期决策，第一期刷评论掏钱，会让他在第二期排前面挣回来；我们用某个数值描述消费者对评论的信任度，越高刷评论越挣钱，但是刷评论会降低它。
3. 实证策略：根据现实情况寻找数据和统计方法验证。比如，如何描述“客户信任”？一种方法是，我们通过看其他平台对评论是否可信的消费者评价。
4. 计算结果：使用模型、算法、数据得出结论，写成论文。

这是一个不靠直觉而靠理解的方法。

形式化推理是其中的核心。社科的数理模型是解释性的模型，而不是自然语言的客观存在，而且会随着事实的改变动态变化；数理模型在学术社区内的传播歧义最少。经济学最好量化和检验，对精确度要求也最高，所以方法论最完备。

## 抽象

我们把这套方法论分为四个步骤：

1. 需求：自然语言描述现象、困惑、猜想、顾虑、风险等。
2. 意图（Intent）：使用形式化语言描述本体的模型、关系、公理、范畴等，以及逻辑关系等。数学上等价就是同一个意图。
3. 规格：使用编程语言无关的逻辑描述系统的编程事实。它和意图之间的关系不是一对一的。数学上等价可以对应不同的规格。
4. 实现：具体的编程语言，可以跑的。

意图（Intent vs Intention）：事实 vs 计划。我们用形式化推理定义Intent以最大限度地减少模糊的Intent传递过程中可能产生的歧义。特点是不完备但是精确。高度依赖AI翻译；避免歧义。计算机的可计算，即规格，要先建立在数学的可计算的基础上。

## 应用

我们再应用回到用于处理经管科研数据的数据工程。

1. 需求：自然语言描述现象。
2. 意图：数理模型描述建模。客户的分析需求，使用数理模型表达。
3. 规格：描述计算机算法。包括数据契约、数据蓝图等等。
4. 实现：具体语言实现。

解决不了的问题回到哲学框架及其数学推理和算法实现，人类不擅长，但是AI擅长。人类通过理解AI的解释判断是否符合自己的需求。

前提是AI的抽象能力已经获得了长足进步，但是描述现实需求的能力依然有限。人机分工转变为，人类负责观察和直觉，AI负责模式学习和结构推理。
